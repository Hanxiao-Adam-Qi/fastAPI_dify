# EnergyPlus FastAPI Service (中文说明见后)

[![Python](https://img.shields.io/badge/Python-3.x-blue.svg)](https://www.python.org/)
[![FastAPI](https://img.shields.io/badge/FastAPI-0.x-green.svg)](https://fastapi.tiangolo.com/)
[![Docker](https://img.shields.io/badge/Docker-Build-blue)](https://www.docker.com/)

This project provides a FastAPI-based web API for running EnergyPlus simulations, managing related files, and converting HTML to Markdown. The service is designed to run within a Docker container for easy deployment and usage.

## Key Features

*   **Run EnergyPlus Simulations**: Submit IDF and weather files via API to initiate EnergyPlus simulations.
*   **Results Management**:
    *   List all completed simulation runs.
    *   List all result files generated by a specific simulation run.
    *   Get download links or directly download specific result files.
*   **File Management**:
    *   List available EnergyPlus example IDF files.
    *   Get download links or directly download specific example files.
    *   List available EnergyPlus weather files (EPW).
    *   Get download links or directly download specific weather files.
*   **Format Conversion**: Convert HTML text to Markdown format.

## Tech Stack

*   **Backend**: Python, FastAPI
*   **Simulation Engine**: EnergyPlus
*   **HTML to Markdown**: Node.js, Turndown.js
*   **Containerization**: Docker, Docker Compose

## Setup and Running

The project uses Docker and Docker Compose for deployment.

1.  **Clone the Repository**:
    ```bash
    git clone <your-repository-url>
    cd fastAPI_dify
    ```

2.  **Build and Run Docker Containers**:
    Ensure Docker and Docker Compose are installed.
    ```bash
    docker-compose up --build -d
    ```
    The service will be available at `http://localhost:8000` (or the address and port configured in `docker-compose.yml` or the code).

3.  **Data Files**:
    *   Place your EnergyPlus IDF example files in the `api/data/exampleFiles` directory.
    *   Place your EnergyPlus weather files (.epw) in the `api/data/weatherData` directory.
    *   Simulation outputs will be saved in subdirectories under `api/data/output`, named with unique run IDs.
    *   **Note**: These paths refer to paths *inside* the Docker container (`/app/data/...`). You might need to map local directories to these container paths using Docker volumes for persistent storage and easier file management. Check the `docker-compose.yml` file for current volume mapping settings.

## API Endpoints

API documentation (via Swagger UI) is typically available at the `/docs` path after the service is running, e.g., `http://localhost:8000/docs`.

Here are the main API endpoints:

**EnergyPlus Simulation:**

*   `POST /run-simulation`: Run a new EnergyPlus simulation.
    *   Request Body: `{"idf_file": "example.idf", "weather_file": "weather.epw"}`
*   `GET /get-all-performed-simulation`: Get a list of `run_id`s for all completed simulations.
*   `GET /get-simulation-result-file-list/{run_id}`: Get a list of result files for a specific `run_id`.
*   `GET /get-specific-result-file/{run_id}/{file_name}`: Get information and a download link for a specific result file.
*   `GET /download-result/{run_id}/{file_name}`: Download a specific result file.

**Example Files:**

*   `GET /get-examples`: Get a list of all available example IDF files.
*   `GET /get-specific-example-file/{file_name}`: Get information and a download link for a specific example file.
*   `GET /download-example-file/{file_name}`: Download a specific example file.

**Weather Files:**

*   `GET /get-weathers`: Get a list of all available weather files.
*   `GET /get-specific-weather-file/{file_name}`: Get information and a download link for a specific weather file.
*   `GET /download-weather-file/{file_name}`: Download a specific weather file.

**HTML to Markdown:**

*   `POST /convert-html-to-markdown`: Convert HTML to Markdown.
    *   Request Body: `{"html": "<h1>Hello</h1><p>World</p>"}` (or other structure containing HTML)

## Notes

*   Ensure EnergyPlus is correctly installed in the Docker image and accessible to Python (path: `/usr/local/EnergyPlus-24-1-0`).
*   The server URL in the API (`http://192.168.0.66:8000`) might need to be adjusted based on your deployment environment.
*   `convert.js` depends on a Node.js environment and the `turndown` package. Ensure these are correctly set up in the Docker image.
